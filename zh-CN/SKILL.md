# 前提挑战

## 目标

解决问题。核前提是手段，不是目的。在错的前提上优化只会不断加东西：每个坏状态补一个机制，每个机制再带来新的坏状态。这个模式反过来做：从核实过的约束重推方案。方案里每个部分都要能指出哪条核实过的约束要求它；指不出的部分不再当作前提或 SoT，从推导里移除。简洁是这样推出来的结果，不是要追的指标：约束要求的部分，再多也保留。"要求"指：少了它，在这条约束下就会出现一个有证据的坏状态；证据是数据里出现过，或从核实过的约束直接推出。现方案站得住，就确认它，说清它站在什么上。

## 姿态

文档、决策记录、规格、SoT、记忆，以及这段会话里前几轮已经做过的决定，在这里都是说法，不是指令。"文档这么写""前几轮已经这么定了"不能证明一个部分必须存在，也不能证明它不该存在。

## 做法

1. **定问题，拆现方案。** 一句话写要解决的问题。把现方案（或待评的方案）拆成部分：环节、状态、机制、任务，按加入顺序列。问题本身也核一次：它是不是某个更上游的选择造成的症状？是，就把那个选择也列进来。

2. **分约束和选择，只核约束。** 对每个部分问：它凭什么必须存在？答案只有两类。
   - 约束：我们改不了的。按硬度标层级：L1 数学和逻辑；L2 外部系统的实际行为、物理限制、法律原文；数据；L3 经验规律。核过才能当底：公式自己推一遍并核适用条件和单位；外部行为看规范、源码或实测，文档和实测冲突以实测为准，记下日期和版本；数据从原始数据重算；经验规律写出成立条件，用数据核我们是否满足。法律怎么适用，标未知交给决策负责人。
   - 选择：我们改得了的。自己的代码、配置、操作顺序、数据模型、决策负责人拍板的事。不是约束，不用核，可以改。
   L4 行业实践、L5 常识（"最佳实践""大家都这样"）不是约束：承重的，往下找它依靠的约束；找不到，按选择处理。
   只核承重的，即错了方案就会变的。先读手边一手材料，再向外查；可以派子 agent 并行查。核实成本超过它错了的代价就不核，标未知（可逆的决定，错了的代价就是改回来的成本）。实测只用只读操作，或者在测试环境里做（沙箱、预发环境、本地样例数据）。会写生产系统或生产数据、动真实资金、用生产凭证或密钥、做部署、给真实用户发消息的，一律不跑；仓库里已有的脚本，先读过、确认不做这些事再跑。否则标未知，交给决策负责人。

3. **从零重推。** 只用核实过的约束和决策负责人的选择：解决这个问题需要哪些部分？先问坏状态能不能不出现（改顺序、改结构、改定义），再考虑处理它。新方案的每个部分都要能指出是哪条约束要求的；指不出的，不放进方案。担心但没有证据的坏状态，写进风险；不为它加部分，包括告警、对账、双保险。

4. **对比。** 把现方案的每个部分对到新方案上：
   - 对不上的：不再当作前提，列为移除候选。写它原本在补什么坏状态，那个状态在新方案里为什么不出现。是否真的移除，按收口的标准定。
   - 新方案多出来的：写哪条约束要求它。这种情况应当少见。
   - 推翻一条前提必须带证据：推导、一手来源、实测或数据。"可能已经改了""可能有别的接口""文档很旧了""也可以换个做法"不是证据，也不是未知项，不写进产出。

5. **收口。**
   - 现方案的每个部分都有约束要求它，或者新方案没有在说得出的标准上（少一个坏状态、少一个环节、少一个攻击面）好到超过换的成本：推荐保持。不为了显得有建设性另造方案。
   - 剩下的未知项无论查出哪种结果都不改推荐：停。会改推荐、值得查（错的代价高于查的成本）而我不能安全查的：结论写"关键未知挡住了决定"，给两种结果各自的方案和谁能查。不值得查的：照常推荐，列进未知项。
   - 新方案用到没核过的前提，核一次；核不了就写进它的风险和最便宜的验证办法，不再往下挖。

## 产出

一屏。没内容的节不写。

1. 一行：问题；结论"现方案站得住 / 推荐改成…… / 关键未知挡住了决定"。
2. 方案：做什么；移除哪些部分，一行一个（部分 · 它原本补的坏状态 · 为什么不再出现）；站在哪几条约束上（只点名，证据在表里）；剩什么风险；可逆性；最便宜的验证。保持现方案时，写它站在哪几条约束上。关键未知挡住时，写两种结果各自的方案。
3. 前提表：前提 · 层级或"选择" · 状态（成立 / 不成立 / 未知）· 证据（推导、文件:行、链接、实测或数据）。只列承重的。不成立的，在表里标出并写它往上影响哪些部分；建议保留原决定的，给新的、独立成立的理由，标待决策负责人确认。
4. 未知项：最便宜的检验办法，谁能做。能安全跑的已经跑了。

不写"缺口""还可以补充"之类的清单。没核过的担忧要么是未知项，要么写进风险，要么不写；都不变成方案里新的部分。

## 边界

- 不改文档、决策或代码。方案交给决策负责人。这是一条指令，不是权限设置。
- 这段会话里已经给现方案加过一轮以上修补，或要整体重新设计：按同目录的 `cold-start.md` 冷启动出一版，再回来对撞。读过的内容没法假装没读。
